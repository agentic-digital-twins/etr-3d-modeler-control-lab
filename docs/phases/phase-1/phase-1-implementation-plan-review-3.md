And **provenance is properly separated now**. The contract distinguishes artifact identity, generator provenance, engineering-source provenance, and lifecycle timestamps. The document explicitly states that generator provenance answers _what produced the artifact_, while `sourceReferences` answers _what engineering evidence informed it_.

That distinction will matter later when Chief needs to distinguish something like:

```text
"This geometry was generated by revision abc123"
```

from:

```text
"This representation of the liner ports is based on
Detroit documentation XYZ, revision N."
```

Those are fundamentally different claims.

Making it structurally defined but optional for the earliest fixture is the right balance.

We aren't going to hold up a synthetic Phase A GLB because it doesn't have a complete engineering bibliography. But when we start the real cylinder in Slice 2, the contract is already capable of answering:

**Where did we get this dimension?**

**Why did we model this feature?**

**Was this based on a manufacturer drawing, photograph, measurement, manual, or reference mesh?**

That could become extremely powerful in Equipment Explorer eventually. A component isn't merely selectable; Chief could someday explain the provenance behind its representation.
